What if we designed the interface around how an LLM works with data?

Agent-Native APIs are an approach to designing data access around the needs of LLM agents. We start with knowledge graphs as a case study; the same design principles can guide interfaces to SQL databases, document stores, and other data services.

The idea

Make the steps explicit.

Accessing data involves several decisions: what information is available, how it relates, what to filter, and what to return.

ANA exposes these decisions as tool calls with named parameters and inspectable intermediate results. The model can use the result of one operation to choose the next. Our first implementation studies this approach on knowledge graphs, where text-to-Cypher expresses those decisions as a formal query.

Text-to-query

Compose a query

Question + schema → generated Cypher → database result.

Correction loops can revise the query after execution or feedback.

Agent-native access

Compose operations

Question → discovery → graph operations → answer handle → rows.

Each step has a contract and can produce state for later calls.

The backend executes the graph operations. The agent is responsible for choosing their sequence and interpreting the results. A successful tool call can still be part of an incorrect answer, so both execution and answer correctness need evaluation.

Interface design

Four decisions that shape the API.

01

Discover before composing

Schema tools expose labels, properties, directions, and examples. Focused inspection helps the model select the parts relevant to a question.

02

Keep intermediate state

A handle identifies a server-side result. Later operations consume that handle; the model can inspect its variables, sample, and lineage without receiving every row.

03

Make limits visible

Traversal caps, row limits, and fetch pagination constrain data movement. Limits differ by operation and are documented in each tool's parameters.

04

Design for composition

Separate filtering, set operations, grouping, and projection let the agent refine an answer. Descriptions explain when an operation fits and what input it expects.

Where MCP fits. MCP can expose these tools through a standard protocol. ANA concerns their semantics: the operations, arguments, returned state, and guidance the agent receives. The same logic can be called through other interfaces.
